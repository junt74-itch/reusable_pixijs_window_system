## 目的

WindowBase が必要とする 3 つの Pixi adapter を入れる。WindowBase 自体はまだ作らない。

移植元: `/tmp/reusable_phaser_window_system` commit `7cfd315`。Phaser API を残さない。Canvas mask fallback は **Drop**。

## 1. Graphics factory + default renderer

`src/core/WindowRenderer.ts` は pixi import しない（GraphicsLike 契約のまま）。

新規 `src/pixi/`:

- `PixiGraphicsFactory.ts` — `createPixiGraphicsFactory(root: Container): GraphicsFactory`。`new Graphics()` を `root.addChild`。`GraphicsLike` は v8 の **shape-then-fill**（`rect(...).fill({ color, alpha })` / `stroke({ width, color, alpha })`）。`beginFill` 禁止。barrel **非公開**
- `windowRendererFactory.ts` — 移植元 `windowRendererFactory.ts` の置換:

```ts
export interface WindowRendererFactoryContext {
  readonly host: PixiWindowHost;
  readonly root: Container;
}
export type WindowRendererFactory = (context: WindowRendererFactoryContext) => WindowRenderer;
export function createDefaultGraphicsWindowRenderer(context): WindowRenderer;
export function resolveWindowRenderer(factory | undefined, context): WindowRenderer;
```

`createDefaultGraphicsWindowRenderer` は `new GraphicsWindowRenderer(createPixiGraphicsFactory(context.root))`。host は context に載せるが factory は root だけ使う（WindowBase が後で host を渡す）。

テスト `tests/pixi/windowRendererFactory.test.ts`:

- stub Container（`addChild` 記録）と stub GraphicsLike でもなく、**fake Graphics を注入できるなら factory 経由で GraphicsWindowRenderer が resize/destroy できること**
- `resolveWindowRenderer(undefined, ctx)` が default を返す
- `resolveWindowRenderer(custom, ctx)` が custom を返す
- WebGL 起動禁止。`new Graphics()` が bun で落ちるなら GraphicsLike stub を root に載せる factory の親子関係だけを試し、default factory の Graphics 生成はソース検査（`new Graphics` と `addChild`）で固定。偽型禁止。失敗したら停止して選択肢を返す

## 2. ContentClipper

`src/pixi/ContentClipper.ts`（公開）。移植元 `src/core/ContentClipper.ts` の **公開メソッド** を維持: `constructor`、`attach`、`updateBounds`、`enable`、`disable`、`destroy`。

置換:

- 第 1 引数は `PixiWindowHost`（Scene ではない）
- `attach(target: Container)`
- mask は hidden `Graphics` を target の子にし `target.mask = graphics`
- クリップ矩形は content-local `{ x: 0, y: 0, width, height }`（padding offset を mask に入れない）。移植元 `tests/core/ContentClipper.contract.test.ts` の座標契約をコピー
- Canvas / GeometryMask パスは **書かない**。ソースに `GeometryMask` / `CANVAS` が無いこと
- Phaser `target.setSize` は Pixi Container に無いのでやらない。clip は mask Graphics の矩形だけ
- `ContentClipperUnsupportedError` は維持（mask を付けられないとき）

テスト `tests/pixi/ContentClipper.test.ts`:

- 座標契約（padding 無視、resize で width/height 更新）
- stub Container + stub Graphics で attach 時に mask が parent され `target.mask` が立つ
- destroy で mask 解除・Graphics destroy
- ソースに phaser / GeometryMask / beginFill が無い
- WebGL 起動禁止

ADR `docs/adr/0001-content-clipping.md` の Port status を Pixi mask（`Container.mask` + local Graphics）に更新。Canvas Drop を再掲。

## 3. PixiWindowInput

`src/input/PixiWindowInput.ts`。移植元 `PhaserWindowInput.ts` の **意味論をコピー**（repeat 初回 400ms、以降 350ms 周期、drag remainder の trunc、gamepad deadzone 既定 0.2、host destroy で dispose）。

Rename:

- class `PixiWindowInput`
- `PixiWindowInputBindings` / `PixiWindowInputOptions`
- 第 1 引数 `PixiWindowHost`
- key は **DOM `KeyboardEvent.code`**（`ArrowUp` / `KeyW` 等）。Phaser `KeyCodes` 数値は使わない
- keyboard は `window` の `keydown`/`keyup`（Browser）。pointer / wheel は `host.stage` の federated event（`pointerdown` / `pointerup` / `pointerupoutside` / `pointermove` / `wheel`）
- gamepad は `navigator.getGamepads`（無ければ skip）。複数 pad は BACKLOG どおり pad 1 相当（index 0）だけ
- `update(deltaMs)` 維持
- timestamp は `performance.now()` または host が渡せる値。`scene.time.now` は無い
- `localToWorld` option 維持

既定 binding（code）: ArrowUp+KeyW、ArrowDown+KeyS、ArrowLeft+KeyA、ArrowRight+KeyD、Enter+Space、Escape+Backspace、PageUp、PageDown、ControlLeft+ControlRight。

テスト `tests/input/PixiWindowInput.test.ts`（jsdom / WebGL 禁止）:

- stub host（`stage.on`/`off` または addEventListener 相当を記録できる plain object）と stub `window` listener
- ArrowUp pressed/released → action `up`
- `update(400)` で repeat
- dispose 後は emit しない
- `host.destroy()` で dispose
- drag started/moved/ended の delta が整数（remainder 蓄積）
- Phaser import 無し

`window` が bun に無い／KeyboardEvent が作れない場合は、テストから呼べる内部 handler を **テスト専用に公開せず**、コンストラクタ option で `keyboardTarget` を差し込んでよい（公開 barrel には出さない）。公開 API を増やさずテスト可能性だけ確保する。
