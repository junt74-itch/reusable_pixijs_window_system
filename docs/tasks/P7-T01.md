# P7-T01 — PixiJS を peer dependency 化する

Status: passed
Assignee: Compose 2.5
Reviewer: Grok 4.6
Phase: 7

## 目的

consumer が所有する PixiJS runtime と library が同じ instance を共有する契約にする。`package.json` の通常 `dependencies` に `pixi.js` があると、consumer 側と異なる version が解決され、`Assets` キャッシュと BitmapFont が二重化する。

## 対象ファイル

- `package.json`
- `bun.lock`（`bun install` の結果）
- `tests/package/pixi-peer-dependency.test.ts`（新規。既存 `public-exports.test.ts` を拡張してもよい）
- `README.md`（PixiJS を consumer が入れる一文だけ。導入節の再構成は P7-T02 / P7-T05）
- `docs/SUBMODULE.md` の「PixiJS ownership」節

`vite.config.ts` の `external: ["pixi.js"]` は **維持**する。内容を変える必要がなければ触れない。

## 変更方針

`package.json` を次の形にする。

```json
{
  "peerDependencies": {
    "pixi.js": ">=8.20.1 <9"
  },
  "devDependencies": {
    "pixi.js": "8.20.1"
  }
}
```

- `dependencies.pixi.js` を削除する。`dependencies` が空ならキーごと削除してよい（空オブジェクトを残さない）
- library 自身の開発・テストは `devDependencies` の exact `8.20.1` を使う
- consumer には PixiJS v8（`>=8.20.1 <9`）を要求する
- `devDependencies` の既存 `three` / `typescript` / `vite` / `@types/bun` は変えない
- `private` / `version` / `exports` / scripts は変えない
- `packageManager` フィールドは **P7-T04** で入れる。本タスクでは足さない

README / SUBMODULE に書くこと（本タスクの範囲）:

- consumer は互換 version の `pixi.js` を親プロジェクトへ入れる
- 対応範囲の正は `peerDependencies.pixi.js`
- ホスト bundler は library と consumer で同じ `pixi.js` 解決先を使う
- `docs/SUBMODULE.md` の「`package.json` の pixi.js dependency（`8.20.1`）」という旧表現を直す

## 実装上の判断（推測しない）

- `peerDependenciesMeta` は足さない
- PixiJS の下限を `8.20.1` より下げない。上限は `<9`
- 公開 barrel・Window 実装・sandbox の import は変えない
- `phaser` を足さない

仕様や公開 API の変更が必要になった場合は実装を継続せず、選択肢を返して停止する。

## 自動テスト

`tests/package` で次を検証する。

1. `dependencies.pixi.js` が存在しない
2. `peerDependencies.pixi.js` が `" >=8.20.1 <9"` 相当（文字列 `>=8.20.1 <9`）
3. `devDependencies.pixi.js` が `"8.20.1"`
4. `vite.config.ts` が `external: ["pixi.js"]` を含む
5. `bun run build` 後の `dist/index.js` が `from "pixi.js"` を含み、PixiJS 本体を inline しない（既存の bundle size < 200_000 でも可。`from "phaser"` が無いことも維持）
6. `dependencies` / `devDependencies` / `peerDependencies` に `phaser` が無い

既存 `tests/package/public-exports.test.ts` の Phaser 検査は壊さない。

## 手動確認

なし。本タスクは metadata と build 契約。

2. library build へ PixiJS 本体が bundle されない
3. consumer 側の PixiJS を使う契約が、短い README 記述と `package.json` と `docs/SUBMODULE.md` で一致する
4. Phaser 依存は 0 件のまま

