# P7-T04 — GitHub Actions で品質ゲートを固定する

Status: passed
Assignee: Compose 2.5
Reviewer: Grok 4.6
Phase: 7
Depends: P7-T03

## 目的

main への変更が unit / typecheck / build / package / consumer typecheck を通ったかを GitHub 上で確認できるようにする。ローカルの `bun run check` は既にあるが workflow が無い。

## 対象ファイル

- `.github/workflows/check.yml`（新規）
- `package.json` — `packageManager` のみ追加
- `tests/package/package-manager.test.ts` または既存 package test への 1 ケース
- README の CI badge は **本タスクでは足さない**（P7-T05。workflow 名が固まってから）

## workflow

```yaml
name: check

on:
  push:
    branches:
      - main
  pull_request:

jobs:
  check:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: "1.4.0"

      - run: bun install --frozen-lockfile
      - run: bun run check
```

- workflow の `name:` は `check`（badge を後で足すときこの名前と一致させる）
- extra job、matrix、cache、browser 実行は足さない
- `permissions` を足すなら `contents: read` のみ。必須ではない
- Bun version は `@types/bun` と同じ **1.4.0**。上げない

## package.json

```json
{
  "packageManager": "bun@1.4.0"
}
```

他の metadata（peer / scripts / private / version）は変えない。

## 実装上の判断（推測しない）

- `bun install --frozen-lockfile` を使い、lockfile 差分がある install は失敗させる
- Actions 上で Playwright / WebGL は走らせない（P7-T06 の HTTP smoke が `check` に入っていれば、それが Actions でも走る）
- `bun-version: latest` にしない
- 別 workflow（lint-only、publish）を作らない

仕様変更や公開 API 変更が必要なら停止する（本タスクでは通常不要）。

## 自動テスト

1. `.github/workflows/check.yml` が存在する
2. `name: check`、`push` の `main`、`pull_request`、`bun install --frozen-lockfile`、`bun run check`、`bun-version: "1.4.0"` を含む
3. `package.json` の `packageManager` が `"bun@1.4.0"`

ファイル内容の契約テストでよい。Actions をこのタスク内から発火する必要は無い。

## 手動確認

なし（workflow が GitHub で緑になる確認は、push / PR 後の人間または P7-T06 レビュー）。

## 非対象

- README badge（P7-T05）
- HTTP smoke の新規設計（P7-T06。既存 `check` に既に入っているものはそのまま Actions で走る）
- branch protection、required checks の GitHub 設定（人間。BACKLOG）
- npm publish
- Bun の version up
- PROGRESS チェックボックス、git commit

## 受入条件

1. push（`main`）と pull request で `bun run check` が自動実行される workflow がある
2. lockfile と差分がある install は失敗する（`--frozen-lockfile`）
3. workflow が実行するコマンドはローカルの `bun run check` と同じ
4. `packageManager` が `bun@1.4.0` である
5. ローカルの `bun run check` が exit 0

## 実行コマンド

```bash
bun run check
```
