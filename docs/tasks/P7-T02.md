## 実働例の要件

import は root barrel だけ。

```ts
import {
  createPixiWindowHost,
  PixiWindowInput,
  MessageWindow,
  ChoiceWindow,
} from "../../index.ts";
```

`from "../src/` / `from "../../src/` を書いてはいけない。型が必要なら同じ `../../index.ts` から type import する。`DEFAULT_BITMAP_FONT_ASSET` は使わない（契約の本文化は P7-T03。本タスクの例も使わない）。

含めるもの:

1. PixiJS `Application` の初期化（`roundPixels: true`、`antialias: false`。論理 960×540）
2. `createPixiWindowHost(app)`
3. consumer 所有の `BitmapFontAsset` を定義し、`Assets.load` する
4. 共有 `PixiWindowInput`
5. `MessageWindow` と `ChoiceWindow` の生成（Message `ownsInput: true`、Choice `ownsInput: false`）
6. ticker から `input.update()` と各 Window の `update()`
7. `say()` から `choose()` までの最小フロー（日本語 1 メッセージ + Continue/Stop 相当でよい。`\f` ページ送りは任意。sandbox の演習キー C/O/H/S/D は **入れない**）
8. Window、input、host の終了処理（`window.destroy()`、`input.dispose()`、`host.destroy()`。`Application` / Assets cache は window が unload しない）

フォント URL は consumer 所有としてソース内で定義する。

```ts
const GAME_FONT: BitmapFontAsset = {
  key: "game-font",
  textureURL: new URL("./assets/fonts/game-font/font.png", import.meta.url).href,
  fontDataURL: new URL("./assets/fonts/game-font/font.xml", import.meta.url).href,
};
```

`/examples/assets/fonts/jf-dot-mplus12/` を文字列として書いてはいけない。`Assets.load` 後に各 `font.pages` の `scaleMode` を `"nearest"` へ設定する。

HTML は Vite `root: "."` で次の URL になる。

```text
http://localhost:5173/examples/consumer/minimal-submodule.html
```

`script type="module"` で `minimal-submodule-runtime.ts` を読む。root `index.html` は **変えない**。

## README への掲載

冒頭近くに「他プロジェクトへ導入する場合」を置き、この順で案内する。

1. submodule 追加
2. consumer 側へ互換 version の `pixi.js` を追加（P7-T01 の peer 範囲）
3. フォント asset を consumer へ配置
4. root `index.ts` から import
5. 最小初期化コード（実働例と同一。import パスも例ファイルと同じ `../../index.ts`）
6. 親プロジェクトの typecheck / build / browser smoke test

本文（コード外）で、親プロジェクトでは import パスを submodule 位置へ、フォント URL を親の asset pipeline へ読み替えると書いてよい。コードブロック自体は実働例と一致させる。

「正式な導入方法は Git submodule のみ」と書く。`bun add git+...` や npm install が使えるように書かない。

既存の `bun run dev` / Three.js overlay / 演習キー表は「このリポジトリを開発・確認する場合」へ移す。`examples/main.ts` は library 内部 sandbox であり consumer 向け導入例ではない、と明記する。

`examples/consumer/readme-example.ts` は **残す**。npm 公開経路としては案内しない。「build 後の package 名 import を型検査する fixture」と書くか、本タスクでは触れず P7-T05 に任せてよい。削除は禁止。

## 実装上の判断（推測しない）

- `examples/main.ts` / `three-overlay.ts` / `three-shared-context.ts` の `src/**` import は **変えない**（内部 sandbox）
- 新しい Window 種、CommandWindow、NineSlice、focus bind は例に足さない
- `tsconfig.consumer.json` の `include` は既に `examples/consumer/**/*.ts` なので、実働例は `typecheck:consumer` に自動で入る。設定を広げすぎない
- `repository-access.test.ts` の「consumer examples do not reference Window classes」は `readme-example.ts` と `submodule-source.ts` 限定のままにする。実働例をその禁止リストへ入れない
- 公開 API を増やさない。`BitmapFontAsset` 型は既存 export を使う

仕様や公開 API の変更が必要になった場合は実装を継続せず、選択肢を返して停止する。
