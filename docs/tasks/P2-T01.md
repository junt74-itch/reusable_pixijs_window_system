## Characterization（自動。WebGL 起動は不要）

`tests/examples/bitmap-font-spike.test.ts` で次を固定する:

1. **XML `base`:** `font.xml` の `<common ... lineHeight="14" ... base="11" ...>`
2. **Pixi parser は `base` を読む:** `node_modules/pixi.js/lib/scene/text-bitmap/asset/bitmapFontXMLParser.mjs` をソース検査し、`baseLineOffset = lineHeight - parseInt(base)` 相当があること（Phaser 版は `data.base` を捨てていた。ここが差分）
3. **期待値:** XML `base=11`, `lineHeight=14` なら Pixi `baseLineOffset` は **3**。コメントで「measurer は XML `base`（または `lineHeight - baseLineOffset`）を使う。Pixi の `baseLineOffset` を `resolveBitmapFontBase` に渡さない」と書く。実装は P3
4. **kerning:** XML は `<kernings count="0" />`。parser ソースが `<kerning>` を読むこと
5. **欠損 glyph:** `missing-characters.txt` の `U+2022`（BULLET）が XML の `<char id="8226"` に無い。ひらがな `あ`（`id="12354"`）は有る
6. **asset 契約:** `DEFAULT_BITMAP_FONT_ASSET` の URL が上記パスと一致。`provenance.json` の `font.xml` sha256 がファイルと一致（`crypto.createHash("sha256")`）
7. **sandbox:** `examples/main.ts` が `Assets.load` と `BitmapText` を使い、`Text`（非 BitmapText）を import しない
8. **src 隔離:** `src/**` に `from "pixi.js"` が依然 0（既存 `public-exports` に任せてよい）

Pixi の XML parser を bun 上で実行しなくてよい（DOMParser 依存）。ソース検査 + XML 文字列で足りる。

## sandbox の load

PixiJS **8.20.1** の公開 API のみ。偽型禁止。目安:

```ts
await Assets.load({
  alias: DEFAULT_BITMAP_FONT_ASSET.key,
  src: DEFAULT_BITMAP_FONT_ASSET.fontDataURL,
});
```

`font.xml` の `<page file="font.png" />` が相対解決されること。`BitmapText` の `style.fontFamily` は spike で実際に解決できる値（asset `key` または XML `info face`）を使い、選んだ値を ADR に一行書く。

`BitmapFont.install` による Canvas 生成フォントは使わない。
